# 表單後端設定教學（給不熟工程的人看的版本）

這個資料夾裡有兩支「腳本」（其實就是一段自動幫你做事的程式）：

1. `form-backend.gs`：讓婚禮網站上的 RSVP 表單，把賓客填的資料自動存進 Google 試算表。**這是主要、正式的回覆管道，務必設定。**
2. `create-google-form.gs`：一鍵生成一份 Google 表單，作為備用回覆管道（例如網站臨時打不開，或有長輩不方便用網頁時）。**這是備用選項，非必要，可跳過。**

以下步驟不需要寫程式，跟著做、依序複製貼上即可。全程約 15–20 分鐘。

---

## 準備工作：你需要一個 Google 帳號

登入你平常用的 Gmail / Google 帳號即可，不需要額外申請什麼。

---

## Part A：設定主要管道（網站表單 → Google 試算表）

### 步驟 1：建立一個新的 Google 試算表

1. 開啟 [Google 試算表](https://sheets.google.com)，點左上角「＋空白」建立一份新試算表。
2. 幫它取個好記的名字，例如「婚禮 RSVP 回覆」。（左上角文件名稱點一下就能改）

### 步驟 2：把後端程式貼進這份試算表

1. 在試算表上方選單，點「**擴充功能（Extensions）→ Apps Script**」。
2. 會開一個新分頁，看到一個空白的程式編輯畫面，裡面預設有 `function myFunction() {}` 這幾行字。
3. 把編輯畫面裡原本的內容**全部刪掉**，改貼上本資料夾 `form-backend.gs` 的**全部內容**（打開該檔案，全選、複製，貼到編輯畫面）。
4. 上方專案名稱（預設寫「無標題專案」）可以改成「婚禮 RSVP 後端」，方便日後辨識。
5. 按左上角的儲存圖示（磁片圖案），或按 `Cmd/Ctrl + S`。

### 步驟 3：（建議）先測試看看能不能寫入試算表

1. 在程式編輯畫面上方，函式下拉選單（原本顯示 `doPost`）改選 `test_doPost`。
2. 按「執行（Run）」（三角形播放鈕）。
3. 第一次執行 Google 會跳出「需要授權」的畫面：
   - 點「檢閱權限」→ 選擇你的帳號 → 若出現「Google 尚未驗證這個應用程式」的警告，點左下角「進階」→ 「前往（專案名稱）(不安全)」→ 「允許」。
   - 這個警告是正常的，因為這是你自己寫（貼上）的私人程式，不是別人上架的公開 App，Google 才會這樣提示，放心允許即可。
4. 執行完成後，回到試算表分頁，應該會看到多了一個叫「RSVP回覆」的分頁，裡面有表頭（時間戳記、Q1 姓名…）和一列「測試姓名」的假資料。
5. 確認沒問題後，可以把這列測試資料手動刪除（直接在試算表上刪除那一整列）。

### 步驟 4：部署成「網頁應用程式」（Web App）

這一步是讓網站可以透過網址把表單資料傳進來。

1. 回到 Apps Script 編輯畫面，點右上角「**部署（Deploy）→ 新增部署作業（New deployment）**」。
2. 左邊齒輪圖示選「類型」→ 選「**網頁應用程式（Web app）**」。
3. 設定：
   - **說明**：可填「婚禮 RSVP 表單 v1」（之後改版可以寫 v2、v3 方便辨識）
   - **執行身分（Execute as）**：選「**我（你的帳號）**」
   - **誰可以存取（Who has access）**：選「**任何人（Anyone）**」
     - ⚠️ 這一步很重要：一定要選「任何人」，不能選「僅限我自己」或「限本機構使用者」，否則賓客的瀏覽器沒有登入你的 Google 帳號會被擋下來，表單送不出去。
4. 按「部署（Deploy）」。
5. 又會跳出授權畫面，跟步驟 3 一樣，一路允許即可。
6. 部署完成後，會顯示一個「**網頁應用程式網址（Web app URL）**」，網址開頭類似：
   ```
   https://script.google.com/macros/s/AKfycb.../exec
   ```
   點旁邊的複製按鈕，把這串網址整個複製起來。

### 步驟 5：把網址貼回網站程式

1. 用文字編輯器（例如記事本、VS Code、或任何能開 `.js` 檔的軟體）打開專案裡的 `js/main.js`。
2. 找到最上面這一行：
   ```js
   const FORM_ENDPOINT = '';
   ```
3. 把單引號中間貼上你剛剛複製的網址，變成類似：
   ```js
   const FORM_ENDPOINT = 'https://script.google.com/macros/s/AKfycb.../exec';
   ```
4. 存檔。

### 步驟 6：測試整個流程

1. 用瀏覽器打開網站（本機預覽方式見專案根目錄 `README.md`），捲到「敬邀您的出席」表單區。
2. 把 15 題都填一份測試資料，按「送出回覆」。
3. 應該會看到綠色勾勾的「已收到您的回覆」畫面。
4. 回到你的 Google 試算表「RSVP回覆」分頁，確認多了一列剛剛填的測試資料。
5. 確認沒問題後，一樣可以把這列測試資料刪除，正式上線前保持試算表乾淨。

### 之後想改後端程式怎麼辦？

如果你之後修改了 `form-backend.gs` 的內容（例如想多加一欄），改完貼進 Apps Script 編輯畫面後：

1. 存檔。
2. 「部署 → 管理部署作業（Manage deployments）」。
3. 點現有部署旁邊的鉛筆（編輯）圖示。
4. 版本選「新版本（New version）」，再按「部署」。
5. **網址通常不會變**，所以 `js/main.js` 裡的 `FORM_ENDPOINT` 不用重貼，但保險起見部署後可以再測試一次步驟 6。

## Part B（可選）：生成備用的 Google 表單

如果你想額外有一份 Google 表單當備用管道（例如傳給不方便點連結的長輩、或當網站臨時有問題時的備援），可以照下面步驟：

1. 開啟 [script.google.com](https://script.google.com)，點「新增專案」。
2. 把畫面內容清空，貼上本資料夾 `create-google-form.gs` 的**全部內容**。
3. 上方函式下拉選單選 `createWeddingRSVPForm`，按「執行」。
4. 一樣會跳出授權畫面，跟前面一樣一路允許。
5. 執行完成後，點下方「執行紀錄（Executions）」或「查看記錄檔（View → Logs）」，會看到三個網址：
   - **填寫用網址**：分享給賓客填寫用（例如貼在 LINE 群組）。
   - **編輯用網址**：只有你自己使用，可以再調整題目、外觀。
   - **回覆試算表網址**：所有 Google 表單版的回覆會自動存在這裡（跟網站版的試算表是分開的兩份）。

### 這份 Google 表單和網站表單的差異（請注意）

Google 表單本身沒辦法像網站一樣，「勾選某個選項後才顯示另一題」做得很細緻自然（雖然 Google 表單有「跳到指定頁面」功能，但顆粒度較粗、且會把 15 題拆成好幾頁，體驗反而變差），所以備用表單做了簡化：

- 網站版：Q5／Q6／Q7 只有在 Q4 選「一定出席」時才會出現；Q11 只有在 Q10 選「紙本喜帖」時才會出現。
- **備用 Google 表單版**：全部 15 題都會顯示在同一頁，Q5／Q6／Q11 改成「非必填」，並在題目下方加了提示文字（例如「僅出席婚宴者需填寫，不出席可留空」），提醒賓客可以視情況跳過。

也就是說，兩份回覆會分別存在兩份不同的試算表裡，新人統計時記得兩份都要看。如果不需要備用管道，Part B 整個可以跳過，不影響網站表單運作。

## 常見問題

**Q：表單送出後，網站顯示「送出失敗」怎麼辦？**
A：最常見原因是 Web App 部署時「誰可以存取」沒選「任何人」，回去 Part A 步驟 4 檢查；或是 `FORM_ENDPOINT` 網址貼錯/漏了 `/exec` 結尾。

**Q：我可以把試算表分享給另一半一起看嗎？**
A：可以，跟平常分享 Google 試算表一樣，右上角「共用」加對方的 Gmail 即可。

**Q：機器人／廣告會亂填表單嗎？**
A：表單裡有一個賓客看不到的隱藏欄位（honeypot），如果有人（通常是機器人）把那欄也填了，後端會直接判定為垃圾訊息、不會寫入試算表，不用擔心。
